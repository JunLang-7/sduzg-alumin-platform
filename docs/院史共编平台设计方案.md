# 院史共编平台设计方案

## 一、功能定位

“院史共编”是校友平台内的院史资料共写功能。它不对游客开放：只有登录后的校友、管理员和超级管理员可以进入。

校友可以查阅已审核发布的院史词条，也可以补充文字、上传图片或扫描资料。每一次编辑都先进入审核，审核通过后才会成为词条正式内容；原有内容不会被直接覆盖，便于保留和追溯院史资料。

本期建议先围绕“词条阅读、校友投稿、图片资料上传、管理员审核、版本记录”形成完整闭环，不加入评论区、匿名投稿或实时多人协作编辑。

## 二、访问与角色

| 角色 | 可以做什么 |
| --- | --- |
| 未登录用户 | 不能进入院史共编模块，也不能查看词条、图片或资料。 |
| 登录校友 | 查看已发布词条；创建或修改词条草稿；上传资料；查看自己的投稿进度和审核意见。 |
| 领域管理员 | 只查看、审核其被授权培养类别内校友提交的内容。 |
| 多领域管理员 | 可同时查看、审核多个被授权培养类别的内容。 |
| 超级管理员 | 可查看全部培养类别内容；管理管理员授权；处理无领域或跨领域的特殊稿件；恢复历史版本。 |

院史共编沿用当前平台已有的数据域授权，不另建一套管理员体系。培养类别严格使用现有三类：**本科、学术学位研究生、MPA**。管理员当前拥有哪些培养类别权限，就审核哪些培养类别校友提交的内容。

例如：

- 本科管理员只处理本科校友投稿；
- 学术学位研究生管理员只处理学术学位研究生校友投稿；
- MPA 管理员只处理 MPA 校友投稿；
- 同时拥有“本科 + MPA”等多个权限的管理员，可以处理相应多个类别的投稿；
- 超级管理员可以看到全部内容，并可调整管理员的授权范围。

## 三、审核如何自动分配

推荐采用“按投稿校友培养类别自动进入对应待审队列”的方式。这种方式最贴合现有平台的数据域授权，规则清晰，也不会让管理员接触无权限的校友内容。

```text
校友提交院史编辑
        ↓
系统读取该校友档案的培养类别
        ↓
本科 / 学术学位研究生 / MPA
        ↓
进入拥有相应数据域权限的管理员待审列表
        ↓
管理员审核通过、退回或驳回
```

系统分配规则如下：

1. 校友提交时，系统自动读取其档案中的培养类别，不允许校友自行选择或修改审核领域。
2. 同一校友如同时具有本院多个培养阶段的校友身份，按其在本院取得的**最高学历**确定审核领域。
3. 投稿自动标记为本科、学术学位研究生或 MPA 之一。
4. 只有拥有该培养类别数据域的管理员能在待审列表中看到该投稿、附件和审核材料。
5. 多领域管理员会在一个待审列表中看到自己所有授权领域的投稿，并带有培养类别标签，方便筛选。
6. 超级管理员始终可查看全部待审内容，并可在特殊情况下手动改派或处理。

这样不需要额外设置“院史办公室组、MPA 教育中心组”等新的审核标签。现有三类培养类别授权已经足够作为第一版的自动分配依据。

### 特殊情况

| 情况 | 处理方式 |
| --- | --- |
| 校友档案没有培养类别 | 进入“待补充领域”队列，仅超级管理员可见；补齐档案后再进入对应领域。 |
| 同一校友具有多个本院培养阶段 | 按本院最高学历进入审核领域。本科与学术学位研究生身份并存时，进入学术学位研究生管理员队列；本科与 MPA 身份并存时，进入 MPA 管理员队列。博士校友在现有授权体系中也归入学术学位研究生领域。 |
| 同时具有学术学位研究生和 MPA 身份 | 两者同属硕士层次时，按校友档案中标记的主培养类别处理；主培养类别缺失时进入“待补充领域”队列，由超级管理员确认。 |
| 内容涉及学院共同历史，而投稿人属于某一培养类别 | 仍按投稿人的培养类别进入对应管理员审核；管理员可标记为“跨领域资料”并提交超级管理员复核。 |
| 同一领域有多名管理员 | 所有人都能看到该领域待审列表；第一版可由管理员自行领取，后续再增加轮流分配和超时提醒。 |

第一版不建议做复杂的抢单、轮询或自动催办。先按培养类别让内容进入正确管理员范围，等管理员数量和实际审核量稳定后，再增加“领取审核、转交、超时提醒”等功能。

## 四、词条与投稿流程

```text
登录校友查看词条
      ↓
补充文字、图片或资料来源
      ↓
提交审核
      ↓
按培养类别进入对应管理员待审列表
      ↓
审核通过：形成正式版本
审核退回：校友补充后再次提交
审核驳回：不发布，但保留处理记录
```

词条页面只展示已通过审核的正式内容。校友提交的草稿、待审材料、退回意见以及未审核图片，只有投稿人和有权限的管理员可以看到。

每次审核通过都会形成一个新版本；历史版本仍保留。若后续发现内容有误，管理员应通过“发布一个修正版本”来改正，而不是直接删除旧记录。

## 五、图片、扫描件与资料要求

图片和扫描件是院史的重要组成部分，但也最容易涉及肖像权、版权和隐私，因此必须与文字一样先审核、后展示。

### 校友上传时

- 可上传 JPG、PNG、WebP 图片和 PDF 扫描件；单个文件不超过 10 MB，每次投稿最多 6 个附件。
- 每一份资料必须填写：资料说明、来源、版权或授权说明。
- 如图片包含可识别的在世个人，投稿人还需确认已取得适当授权。
- 上传完成并不代表已发布；文件仅供投稿人和对应领域管理员在审核阶段查看。

### 管理员审核时

- 核对图片或扫描件是否与词条内容相关；
- 核对资料来源是否明确；
- 核对是否涉及不宜展示的个人信息、肖像或联系方式；
- 通过后，图片或扫描件才会随正式词条版本向登录校友展示；退回或驳回的附件不对其他校友显示。

### 存储原则

系统直接复用现有平台的 MinIO 文件存储和上传方式，不新增新的网盘或第三方服务。附件先保存在审核区，审核通过后才进入正式词条版本；所有图片均需经过登录和权限检查后才能预览，不设置互联网公开链接。

## 六、页面设计（精简为三个入口）

院史共编作为登录后顶部导航中的一个入口，紧跟“用户中心”。不新增复杂的多级菜单，也不把每个操作拆成独立页面。

1. **院史共编词条页**：目录、搜索、正文、参考资料、已审核图片和版本记录集中展示；点击“参与编辑”后在当前页面打开编辑抽屉，填写正文、资料来源、修改说明并上传图片或扫描件。
2. **我的投稿**：作为院史共编词条页中的标签页，校友查看自己的草稿、待审、已通过、退回和驳回记录，不再单独跳转一个页面。
3. **领域待审**：仅管理员可见。待审列表与审核详情在同一页面完成：点击某条投稿后打开详情抽屉，对比原内容、新内容和附件，并执行通过、退回或驳回。

管理员授权继续沿用现有管理员授权页面，不为院史共编单独新增授权页；本科、学术学位研究生、MPA 三类权限仍由超级管理员在原页面配置。

## 七、第一版需要增加的内容

第一版只增加与院史共编直接相关的内容：

- 院史词条、版本、投稿、附件和资料来源的记录；
- 院史词条阅读、编辑抽屉、我的投稿标签页和领域待审页面；
- 按本科、学术学位研究生、MPA 三类培养类别筛选投稿与待审内容；
- 图片和扫描件的审核期存储与发布后展示；
- 投稿、审核、发布、退回等处理记录。

不需要新增新的账号类型、新的管理员分组或新的培养类别；直接复用现有本科、学术学位研究生、MPA 三类授权方式。

## 八、验收标准

- 未登录用户不能访问院史词条、图片、投稿和审核页面。
- 本科、学术学位研究生、MPA 校友的投稿，只会被拥有对应培养类别数据域的管理员看到。
- 多领域管理员只能看到自己被授权的领域；超级管理员能看到全部领域。
- 校友不能看到其他校友的草稿、待审资料或审核意见。
- 图片和扫描件未审核前不对其他校友展示；审核通过后才随词条版本展示。
- 每次通过审核都会保留一个可追溯的院史版本和处理记录。
