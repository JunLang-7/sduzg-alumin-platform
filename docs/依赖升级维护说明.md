# 依赖升级维护说明

GitHub 从默认分支 `main` 的 `.github/dependabot.yml` 读取配置。配置通过 PR 合并到 `main` 后生效，无需维护其他长期分支的副本。

所有版本升级 PR 的目标为默认分支 `main`，每周检查以下范围：

- `/server` 的 Go modules。
- `/web` 的 npm 依赖。
- GitHub Actions。
- `/server` 和 `/web` Dockerfile 的构建及运行镜像。

Go 与 npm 升级沿用按生态分组，只包含 patch/minor；Actions 同样忽略 major。Docker 镜像只自动提出 patch 更新，以保持 Go 1.26、Node 22 等工具链系列稳定。major 更新以及 Docker minor 更新应创建独立 Issue，核对兼容性和工具链后人工升级。提交前缀为 `chore(deps)`、`ci(actions)` 或 `build(docker)`，符合仓库提交标题要求。

## 当前安全基线

Go 工具链和 API 构建镜像同步使用 1.26.9；x/net 至少为 0.60.0、x/text 为 0.42.0（由 x/net 0.60.0 要求，已包含 0.41.0 的漏洞修复）。此补丁只修复当前漏洞所需依赖，未合并现有机器人 PR 的全部升级。Axios 固定为 1.20.0，修复 npm audit 报告的高危漏洞。govulncheck 与 npm audit 仍使用实时数据库，并保留原有扫描门禁。

Excelize 固定为 `v2.11.1-0.20261003002531-6258dcebc4e2`（伪版本）。v2.11.0 有 15 条已公开的“畸形工作簿”告警（9 high / 6 medium），修复只进入上游 master，Go proxy 的 `@latest` 仍为 v2.11.0，因此 Dependabot 的安全更新以 `security_update_not_found` 失败，只能手工固定。导入接口会解析用户上传的 xlsx，`OpenReader`、`Rows().Columns()` 正落在受影响 API 上：回归测试 `server/internal/service/alumni_workbook_hardening_test.go` 用构造文件在 v2.11.0 上触发 `makeslice: cap out of range`，在固定版本上得到 `unzip size exceeds the 16777216000 bytes limit` 错误。**上游发布 v2.11.1 后应切回正式 tag**，切换前先确认该回归测试仍然通过（测试在 v2.11.0 上以 panic 失败，可拦住降级）。`govulncheck-allowlist.txt` 中的 `GO-2026-6452` 仍保留：其 fixed 事件缺失属上游漏洞库问题，与本版本固定无关。

Go 与 npm 的安全更新不留给每周检查：Dependabot 无法开 PR 的场景（如上述伪版本）由维护者手工固定在 `go.mod`、`package-lock.json`，并用回归测试把住版本，而不是依赖 CI 绿色推断安全。

配置生效不会让旧 PR 重新获得新的 Go 基线。修复合并到 `main` 后，需要更新或重建已有机器人 PR；旧的 npm major 分组 PR 应关闭并按新范围重新生成。

## 处理升级 PR

1. 阅读机器人 PR 的依赖变更与发布说明，补充必要的验收证据。GitHub 记录的 PR 作者必须同时为 `dependabot[bot]` 且类型为 `Bot`，才豁免关联 Issue；普通 PR 仍需 `Closes #编号`。此豁免不依据分支名或 PR 标题，也不跳过 Linked issue 检查任务。
2. 验证提交标题、基础质量、安全扫描、集成测试和 E2E；出现破坏性变更时修复兼容性后再提交。
3. 保持人工评审、讨论解决和线性历史要求，通过后合并到 `main`；需要发版时，在 `main` 上的已验收提交打版本标签。

机器人只提出升级 PR，不会自动合并。Go Docker 镜像升级不代表 `server/go.mod`、CI 固定的 Go 版本或项目文档已经同步更新；升级工具链时需逐项核对。漏洞扫描使用实时漏洞数据库，历史绿色 CI 不能保证当前依赖安全。

配置不设置 `target-branch`，版本更新和安全更新均使用默认分支 `main`，避免非默认目标分支使安全更新无法沿用相应配置。Dependabot 安全更新仍需在仓库安全设置中启用；当前已知漏洞需要及时处理，不能等待每周版本更新。

参考：[Dependabot 配置文件](https://docs.github.com/en/code-security/concepts/supply-chain-security/about-the-dependabot-yml-file)、[配置选项](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference)。
