# v0.6.0 — 政管全球校友数字化平台和院史在线平台六期

本次为六期功能版本，核心是**一人多段学籍与独立档案管理**：个人主档案与学籍培养信息分离，一名校友可同时拥有本科、硕士、博士多段学籍，档案文件、数据域授权、操作审计全部按学籍段独立管理。同时完成三类配套：学籍级删改与培养类别更正（#243）、发版前回归修复（#252），以及生产配置与依赖安全加固。不引入新业务模块，管理员数据域与功能权限边界不变。

## 新增功能

### 一人多段学籍与独立档案管理（#241）

- **模型拆分**：新增 `alumni_enrollments` 学籍表，个人共享字段（姓名、手机号、工作单位等）与学籍培养字段（培养层次、年级、班级、培养类别）分离；迁移为每位旧档案建立一段学籍，学术学位研究生历史数据保留「待核验」层次，升级后可人工更正。
- **按学籍授权**：数据域归属从个人下沉到学籍段。列表按人去重展示，学籍筛选要求命中同一个人同一段学籍；详情、附件、导出均按学籍段的数据域裁剪，跨域学籍不可见、不可改。
- **档案文件绑定学籍段**：附件从「属于人」改为「属于学籍段」。编辑过程中上传的文件先进入草稿（仅当前操作者可见），「保存全部修改」提交后才激活为正式附件；取消编辑不影响任何正式附件，其他管理员的草稿互不干扰。
- **保存全部修改**：个人信息与多段学籍在一次事务中原子提交，乐观锁 `version` 校验，与他人并发编辑冲突时返回 409 并提示重新加载；学籍标记删除、培养类别更正与个人信息修改一并生效。
- **前端编辑体验**：管理端编辑弹窗分「个人信息」与「学籍和档案」两区，学籍按本科 → 硕士 → 博士 → 待核验统一排序；本人资料页只读展示全部学籍；数据大屏按人展示并兼容学籍段筛选。

### 学籍独立删改与培养类别更正（#243）

- **软删除学籍**：已保存学籍可标记删除并可撤销，保存后生效；删除保留个人身份、其他学籍与该段正式附件，仅最后一段有效学籍拒绝删除（409）。
- **培养类别更正**：培养层次与培养类别组合校验（如本科只能属于相应培养类别），更正需要管理员同时拥有原类别与目标类别的数据域权限；编辑弹窗按层次过滤可选类别，唯一合法时自动选中。
- **保存后失去访问权**：若删除的是操作者唯一可维护的学籍段，保存以成功响应返回 `data=null`，前端提示并返回列表，不再误报失败。
- **审计细化**：学籍删除与类别更正分别写入带学籍 ID 与类别归属的审计事件，操作历史可精确到段。

## 优化与修复

### 学籍升级、附件清理与导入一致性（#252）

- 整人删除收敛为事务化操作：按与保存一致的顺序锁定个人、学籍、文件，要求只剩一段有效学籍且操作者有权维护全部历史学籍；多段有效学籍与存在无权维护的历史学籍分别返回明确冲突提示。删除事务内级联软删除正式、草稿与待上传文件，提交后清理对象存储；上传与删除交错时禁止在已删除学籍上创建新文件，关闭竞态窗口。
- 校友本人更新手机号、邮箱会推进乐观锁版本，管理员持有过期版本的并发保存返回 409，不再静默覆盖本人联系方式修改。
- 批量导入去重查询改为行构造 IN 分批执行，20000 行全量导入不再触碰 MySQL 预处理参数上限；显式指定导入目标培养类别时校验其处于启用状态、且与行的培养层次匹配，不匹配逐行报错。
- 迁移 012 升级路径修复：旧库已删除档案的附件与无详情操作日志此前会被跳过，现一并回填；遇到无法归属的孤儿附件迁移主动中止并保留旧 ID 供核对，修正后可重跑。CI 升级演练脚本同步覆盖这些场景。

### 认证与登录态（#226）

- 数据库中角色缺失或非法时按拒绝访问处理，不再默认放行；无效角色账号拒绝登录。前端登录态清理同步补齐，并新增未登录/越权访问的回归测试。

### 生产配置加固（#246）

- `APP_ENV=production` 时校验 `AUTH_JWT_SECRET`：空值、默认值或长度不足直接启动失败并打印明确原因，不再带默认密钥上线；Compose 将其声明为必填，未配置在 `up` 阶段即报错。部署文档补充密钥生成与轮换说明。

### 部署收敛（#247）

- Compose 中 MySQL、Redis、对象存储与 API 默认绑定 `127.0.0.1`，仅 Web 对外开放；CI 校验默认端口绑定防止回退。`SWAGGER_ENABLED` 默认关闭，本地联调需显式打开。
- 部署文档新增上线安全检查清单与数据时区自查章节，附一次性时区修复脚本（默认只读预检，确认命中后人工核对执行）。

### 发布流程稳定性（#224）

- Release 工作流对「托管 runner 被宿主回收」这类基础设施中断自动整体重跑（最多 3 次），E2E 超时放宽，减少发版时的人工重跑。

## 安全加固

- **Go 工具链升级到 1.26.11**（#239）：修复标准库安全漏洞，`go.mod`、Dockerfile 与 CI 同步更新。
- **follow-redirects 固定到 1.16.2**（#230）：修复 `GHSA-mrwp-f3q8-3g9p`（影响 1.16.0–1.16.1），改由 npm `overrides` 钉住版本防止间接降级。
- 依赖组例行升级（#228、#231–#235、#248、#249、#251）：`excelize`、腾讯云 SDK、`zustand`、`@playwright/test`、`vitest`、`minimatch`、`typescript-eslint` 及 Go 依赖分组。

## 数据库变化

新增 `012_add_alumni_enrollments.sql`：

- 创建 `alumni_enrollments` 表并为每位旧档案建立一段学籍；`alumni_files` 增加 `enrollment_id` 外键并回填绑定（含已删除档案的附件）；`alumni_profiles` 增加乐观锁 `version` 列。
- 操作历史按原档案数据域回填 `data_domain_ids` 归属（含无详情的旧日志），保证升级后普通管理员仍按原范围可见。
- 旧列（`alumni_profiles.data_domain_id`、`alumni_files.alumni_id` 等）在回填完成后清理；迁移幂等可重跑，遇到无法归属的孤儿附件将主动中止并保留旧 ID 供核对。

## 升级说明

- 升级前按 `docs/deployment.md` 流程备份数据库与对象存储，并在备份库预跑迁移；迁移会为 6700+ 量级档案一次性建立学籍，生产数据已按此路径演练通过。
- 若预跑报 `unmapped alumni_files`，按保留的 `alumni_id` 对照备份修正归属后重跑迁移；此前已在开发环境运行过旧版 012 的，旧关联只能从升级前备份核对。
- 升级后核对：每份旧档案恰好一段学籍、附件均已绑定学籍段、账号关联保留、操作历史可按原范围查看。
- 回滚依赖升级前备份而非反向迁移；对象存储对象键未改动，回退版本镜像即可。
- 升级前确认生产 `.env` 已配置足够强度的 `AUTH_JWT_SECRET`（新版生产环境将强制校验），并核对 Compose 端口绑定符合预期。
