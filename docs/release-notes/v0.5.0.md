# v0.5.0 — 政管全球校友数字化平台和院史在线平台五期

本次发布在 v0.4.0 院史共编与授权体系之上，补齐词条删除申请与交叉审核、Markdown 编辑工具栏与六级目录、Swagger 接口文档三项能力，收紧校友端通用档案查询权限，并修复导入链路与依赖的安全问题。平台正式更名为「政管全球校友数字化平台和院史在线平台」。

## 版本亮点

- 院史词条删除改为「申请 + 交叉审核」流程：普通管理员不能直接删除，也不能自审；由其他同域管理员审核，超级管理员保留直接删除权。
- 院史编辑器新增 Markdown 工具栏、快捷键与实时预览；正式词条支持六级标题目录跳转与当前章节高亮。
- API 服务新增 Swagger 在线接口文档，覆盖全部 57 个接口；从文档发起的请求与手工调用走同一套权限校验。
- 通用校友档案查询接口收紧为仅管理员可用，校友令牌访问返回 403。
- 批量导入链路安全加固：超限时提前停止读取工作簿，并升级含安全修复的依赖版本。

## 新增功能

### 院史词条删除申请与交叉审核

- 校友无删除入口与删除权限；普通管理员对所属数据域词条提交删除申请，不能直接删除，也不能审核自己的申请，待审队列排除本人申请。
- 其他拥有对应数据域权限的管理员可以驳回或同意申请；超级管理员可审核全部申请（含本人），并保留直接删除词条的权限。
- 管理员直接删除词条时需二次确认，删除失败有明确提示；删除后词条不再展示，历史投稿、版本和附件记录保留。
- 院史页展示「我的删除申请」与审核意见；待审页可查看删除原因并处理。

### Markdown 编辑工具栏与六级目录

- 院史编辑器新增工具栏，覆盖加粗、斜体、多级标题、任务列表、链接等常用操作，并提供快捷键（如 Ctrl/⌘+B、Ctrl/⌘+I、Ctrl/⌘+Alt/⌥+数字切换标题层级、Ctrl/⌘+K 插入链接）。
- 编辑与预览双标签切换；修复连续格式命令的选择区竞态和表单旧值回写问题。
- 标题快捷键改为要求精确修饰键组合，不再因多按 Shift 而误触发。
- 链接处理补充特殊字符转义；移动端窄屏下工具栏可用且不溢出。
- 正式词条右侧「本页目录」支持一至六级标题跳转，滚动时高亮当前章节。

### Swagger 接口文档与在线调试

- API 服务挂载 `/swagger/index.html`，规范端点 `/swagger/doc.json`，覆盖 57 个接口（48 条唯一路径）、10 个模块分组；文档入口是 API 端口（默认 8080），Web 容器不代理该路径。
- 在 Authorize 中填入令牌后可直接发起真实请求；文档入口不放宽任何登录、角色、数据域与功能权限校验。
- 新增 `SWAGGER_ENABLED` 配置：未设置时非生产环境开启、`APP_ENV=production` 时关闭；本地 Compose 显式开启，公开部署应设为 `false`。
- 新增 `make swagger`；CI 重新生成并断言接口注解与生成文档一致，规范与实际注册路由双向比对。

### 文档体系与 GitHub Wiki 同步

- 新增面向使用者的《平台使用说明》，按角色覆盖登录、资料维护、院史共编、校友管理与数据大屏。
- 新增覆盖全部 57 个接口的《接口文档》，含请求/响应、分页、错误码、权限约束与调用示例。
- 仓库文档自动同步 GitHub Wiki（平台使用说明、部署说明、接口文档、版本发布记录），仓库为唯一源。
- 精简 README 并整理文档导航；补齐 v0.1.0—v0.3.1 历史发布说明；移除已过期的需求与方案文档。

### 平台更名

- 前端展示层统一更名为「政管全球校友数字化平台和院史在线平台」，去除「MPA 试点」字样；数据大屏更名为「全球校友数据驾驶舱」。
- 首页与登录页结构同步精简。接口、数据库与权限逻辑不变。

## 安全加固

- 通用校友档案查询（`GET /api/v1/alumni`、`GET /api/v1/alumni/:id`）收紧为仅管理员访问：校友令牌返回 403；本人资料、联系方式与院史接口不受影响。
- 升级 `excelize` 到包含「畸形工作簿」安全修复的版本（原 v2.11.0 有 15 条公开告警），并补充能拦住降级的回归测试。
- 批量导入超限时在读取阶段提前停止，不再整表物化，内存占用与工作簿声明的行号解耦；超限错误从 500 内部错误改为 400 业务提示。
- 升级 `source-map-js`（修复已知 DoS 漏洞）与开发链中的 `brace-expansion`；CodeQL 两条前端告警经评估后关闭并在文档留痕。

## 优化与修复

- E2E 环境显式关闭登录限流，本地 `.env` 不再影响 `make e2e`；修复删除申请提交的导航竞态。
- 院史 E2E 用例可在同一环境重复执行；目录跳转断言改为「点击前目标必须在视口外」，滚动失效时测试会失败而不是照常通过。
- 升级路径验证支持含 `006` 的基线（如 v0.4.0），并依次验证上一发布标签、v0.3.1 与退化基线三条路径；`migrate.sh` 支持 `MIGRATIONS_DIR`，可在无 `/migrations` 写权限的环境运行。
- 简化为 `main` 单长期分支流程：CI 只监听 main，正式版与预发布标签均校验 main 提交归属。
- CI 依赖升级到 node24 最新版本（`actions/setup-go` v7.0.0、`upload-artifact` v7.0.2、`download-artifact` v8.0.2），消除持续出现的 Node.js 20 弃用告警；同时解除 `dependabot.yml` 对 `github-actions` 的 major 屏蔽，避免同类告警再次积压。
- CI runner 由 `ubuntu-latest` 显式固定为 `ubuntu-26.04`：既避开 `ubuntu-latest` 灰度迁移到 Ubuntu 26 期间镜像版本不确定，也与生产服务器（Ubuntu 26.04 LTS）保持一致。
- Docker 构建支持 `GOPROXY`、`NPM_REGISTRY`、`APK_MIRROR` 构建参数，便于受网络限制的环境构建。
- 首页、登录页与院史页视觉细节调整。

## 数据库变化

新增 `010_add_history_deletion_requests.sql`：

- 新建 `history_entry_deletion_requests` 表，记录院史词条删除申请及审核结果（申请原因、状态、审核人、审核意见与时间）。
- 待审申请对词条唯一，避免同一词条出现重复待审；按申请人与「数据域 + 状态」建立索引。
- 不修改既有表结构，存量数据无需回填。

## 升级说明

- 旧数据卷无需重建：`docker compose up --build` 时由 `migrate` 服务增量应用 `010`；不要为升级执行 `docker compose down -v`。
- 升级路径已在 CI 中按 v0.4.0（上一发布标签）、v0.3.1 与退化基线完整验证，含重复执行幂等。
- 行为变化：外部脚本若使用校友令牌调用通用档案查询接口，升级后将得到 403，请改用管理员令牌。
- 公开部署必须：更换默认管理员密码与数据库凭据、显式传入 `AUTH_JWT_SECRET`、将 `SWAGGER_ENABLED` 设为 `false`；升级前照常备份数据库与对象存储。

## 已知限制与后续优化

- 访问令牌仍存储于 `localStorage`；后续计划补齐 CSP，并评估迁移 httpOnly Cookie 与 CSRF 防护（处置记录见《依赖升级维护说明》）。
- 院史共编的编辑表单与搜索体验仍在持续打磨。
