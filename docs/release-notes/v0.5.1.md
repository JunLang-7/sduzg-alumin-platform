# v0.5.1 — 政管全球校友数字化平台和院史在线平台五期修复

本次为五期修复版本，集中解决三类线上问题：操作历史在大数据量下报 500 与时间显示错位、导出与导入无法闭环、发版后部分用户长期停留在旧版前端；同时完成两项高危依赖修复与 Nightly 误判处理。不新增业务模块，不改变权限模型与数据域规则。

## 优化与修复

### 操作审计：列表稳定性与时区口径

- 操作历史列表此前在 `created_at` 上做 filesort，MySQL 会在排序前把包含整块 `detail` 的行物化进 `sort_buffer`；单条批量导入审计的 `detail` 可达数百 KB，超过默认 256KB 即报 `1038 Out of sort memory`，列表接口直接 500。新增复合索引 `idx_logs_created_id (created_at, id)`，列表排序改为反向扫描索引，排序结果与 `detail` 体积彻底解耦。
- 列表接口不再返回 `changes`、`batch_created_alumni` 等明细字段，只返回展示所需字段；详情接口仍返回完整 JSON。
- 单条导入审计最多保存前 200 条明细，超出时返回真实创建总数 `batch_created_alumni_total` 并置 `batch_created_alumni_truncated: true`，前端提示「仅展示前 N 条，共 M 条」。审计详情因此不再随导入条数无限增长。
- Compose 为 MySQL 显式设置 `--sort-buffer-size=8M` 作为兜底。

### 时间展示与筛选口径统一

- 操作历史列表、详情抽屉、校友历史卡片此前直接截断 UTC 字符串，页面显示比真实时间早 8 小时。新增统一时间工具 `web/src/utils/datetime.ts`，按浏览器本地时区格式化，院史、Wiki、校友档案与数据大屏一并收敛。
- 日期筛选改为把本地开始日 00:00、结束日次日 00:00 换算成 UTC 瞬时，通过新增的 `start_at` / `end_at` 传给后端（RFC3339，左闭右开），筛选区间与列表展示为同一时区口径；夏令时切换日可能是 23 或 25 小时，不按固定 24 小时处理。旧 `start_date` / `end_date` 保留，仍按 UTC 日边界解析。
- 非法日期不再静默忽略，返回 400 业务提示。

### 校友导出与导入闭环

此前导出是 15 列、导入模板是 16 列，导出文件无法回灌；CSV 只能看不能用；全量导出超过导入上限。本次补齐：

- **导出补齐所属领域**：xlsx 与 csv 固定输出 16 列，在原有 15 列之后追加「所属领域」，值为数据域编码，列顺序与导入模板完全一致；原有 15 列顺序不变。导出一次加载数据域映射（含已停用数据域），不产生 N+1。
- **导出文件可直接回灌**：不附加 `data_domain_id` 直接导入不再返回 400；全部命中去重时返回逐行「已存在」，而不是格式错误。回灌只做新增与去重跳过，不覆盖更新。
- **支持 CSV 导入**：UTF-8 `.csv` 自动剥离 BOM，与 xlsx 共用表头、领域解析、去重与空白行逻辑；含逗号、换行、双引号的字段正常往返。
- **导入上限提升**：单次导入从 5000 条提升到 20000 条（按物理行数，含空白行），覆盖当前全量导出规模。CSV 与 xlsx 共用同一上限，且都在读取阶段提前止损，大文件不会被全量物化。
- **所属领域填写容错**：可填编码（大小写不敏感）、显示名称或数字 ID；非法值返回逐行错误并列出可选值。模板新增「填写说明」工作表，列出三种培养类别的编码与显示名称对照、填写规则与示例。
- **跨域不再静默改写**：单域管理员的 16 列文件留空所属领域时按唯一授权域处理，填写其他域则逐行报错；不再把别人的档案静默塞进本域。已停用数据域的档案可以导出编码，但回灌时明确拒绝。
- **空文件不再报成功**：只有表头或全部为空白行的文件返回 400「文件里没有可导入的数据行」，不再显示「全部导入成功，无错误记录」。
- **防公式注入前缀往返无损**：导出会给 `= + - @` 开头的值加 `'`；回灌时自动还原。值本身以 `'` 开头时导出再加一层、导入只剥一层，因此往返不再丢字符。
- **表头错误归为 400**：非工作簿、非 CSV 的随机文本从 500 内部错误改为 400「表头不正确，应使用 15 列通用模板或 16 列含所属领域模板」。
- **导出快照告警**：导出时统计姓名为空或年级为空的行并记录告警日志——这类历史数据可以导出，但回灌必然被逐行拒绝，需要先在数据侧修正。

### Web 静态资源缓存

- 入口 HTML（`/`、`/index.html` 及 SPA 深层路由回退）改为 `Cache-Control: no-cache`，允许缓存但每次向服务器校验，配合 ETag 命中返回 304。此前没有任何缓存头，浏览器按启发式缓存长期复用旧入口，导致发版后部分用户停留在旧版。
- `/assets/` 下 Vite 生成的带内容 hash 产物改为 `public, max-age=31536000, immutable`。
- nginx 增加 `server_tokens off`（不再暴露版本号），`/assets/` 关闭访问日志。
- 行为变化：请求不存在的 `/assets/*` 以前返回 `200 text/html`（浏览器报 MIME 错误），现在返回 404。

## 安全加固

- **Go 工具链升级到 1.26.10**：修复 `GO-2026-6809`（`crypto/x509`）。`server/go.mod`、`server/Dockerfile` 与文档中的版本同步更新——Dependabot 的 Docker 分组只改镜像，不会同步 `go` 指令与 CI 的 `go-version-file`。
- **follow-redirects 升级到 1.16.1**：修复 `GHSA-q3jh-wrc6-jgq8`、`GHSA-8r9p-f939-6h3c` 两条高危（axios 的传递依赖）。仅修改锁文件，axios 声明范围已覆盖；新增回归测试钉住版本下限与单副本，防止被间接降级。
- 开发依赖升级：`@playwright/test` 1.64.1、`vitest` 5.0.5；`gorm.io/hints` 1.1.2。
- 缓存头、`If-None-Match` 协商缓存、缺失资源 404 与 `Server` 头的断言纳入 CI，`server_tokens off` 与 `/assets/` 的 404 行为都有回归测试。

## CI 与开发流程

- Nightly 失败时区分「托管 runner 被宿主回收」与真实测试失败：新增 `classify-run-failure.sh`，按 job 注解与运行日志判定，只有所有失败 job 都只剩 shutdown + 143 痕迹时才判定为基础设施中断，并自动重跑一次（最多 3 次尝试）。
- 所有 job 补齐 `timeout-minutes`，真正的超时不再退化成静默的退出码 143。
- `containers` 任务新增入口 HTML 协商缓存、`/assets/` 长期缓存、`If-None-Match` 返回 304、缺失资源 404 与 `Server` 头断言。
- 补充依赖安全回归测试与《依赖升级维护说明》中的告警处置记录。

## 数据库变化

新增 `011_add_audit_log_sort_index.sql`：

- 为 `operation_logs` 增加复合索引 `idx_logs_created_id (created_at, id)`，支撑操作历史列表的有序扫描，避免 filesort 触发 `1038 Out of sort memory`。
- 迁移可重复执行：MySQL 不支持 `ADD INDEX IF NOT EXISTS`，脚本先查 `information_schema.statistics` 再建索引，兼容数据卷首次初始化与 `migrate.sh` 二次应用。
- 不修改表结构、不改写存量数据、无需回填。

## 升级说明

- **必须执行迁移 `011`**：`docker compose up --build` 时由 `migrate` 服务自动增量应用；不要为升级执行 `docker compose down -v`，否则会丢数据。缺少该索引时列表查询会降级执行并产生告警，但大数据量下仍可能报 1038。
- **必须核对 `DB_PARAMS`**：本版本把数据库连接固定为 `loc=UTC&time_zone=%27%2B00%3A00%27`，保证 `DATETIME` 按 UTC 解析、会话时区固定为 `+00:00`。旧部署的 `server/.env` 若仍是 `loc=Local`，需手工更新——旧文件不会随示例自动更新。MySQL 启动参数需重建容器才能生效，保留数据卷。
- **需要重建 API 与 Web 镜像**：API 含导入导出与审计改动，Web 含 `nginx.conf` 缓存策略；无新增环境变量。
- **浏览器侧一次性操作**：已缓存旧入口 HTML 的客户端仍需硬刷新（或清除站点数据）一次，之后不再复发。Safari 的前进/后退页面恢复（BFCache）不受 HTTP 缓存头约束，如仍遇到「后退看到旧页面」，属于另一个问题。
- **对外格式与接口变化**：
  - 导出文件由 15 列变为 16 列，仅在末尾追加「所属领域」，前 15 列顺序不变；按列号读取旧列的外部脚本不受影响。
  - 操作历史列表不再返回 `changes`、`batch_created_alumni` 等明细字段，需要明细请调用详情接口。
  - 导入新增 CSV 支持、上限提升到 20000 条；表头错误由 500 改为 400。
  - 不存在的 `/assets/*` 由 `200 text/html` 改为 404。
- **发布后建议执行一次历史数据排查**：旧版本在「导出 → 回灌」时可能把防注入前缀当成真实内容写回库（例如手机号被存成 `'+8613800000000`）。本次修复只对新导入生效，不会自动修正历史记录；排查 SQL 见 `docs/deployment.md` 的「历史公式前缀数据清理」一节，确认命中后逐条人工核对再清理，操作前先备份。

## 已知限制与后续优化

- 无敏感字段权限的管理员导出的是脱敏文件（手机号等列为空），**不要用于回灌**：去重键包含手机号，回灌时命中不了已有记录，会重复建档。已在文档中显式警示。
- 已停用数据域的档案可以导出，但不能回灌。
- 历史数据中姓名为空或年级为空的行可以导出，但无法回灌，需要先在数据侧修正。
- 访问令牌仍存储于 `localStorage`；后续计划补齐 CSP，并评估迁移 httpOnly Cookie 与 CSRF 防护。
