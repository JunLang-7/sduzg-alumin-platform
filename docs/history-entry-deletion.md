# 院史词条删除审核

校友不能申请或执行删除。普通管理员可对所属数据域的词条填写原因并申请删除，不要求词条由本人投稿；必须由其他拥有对应数据域权限的管理员或超级管理员审核。普通管理员不能同意或驳回自己的申请，待审队列排除本人申请，在院史页“我的删除申请”跟踪结果。

超级管理员可以申请删除全部词条，并审核本人或其他管理员的申请；保留直接删除权限。普通管理员不能调用直接删除接口绕过审批。

申请待审时词条继续展示，驳回后可以重新申请。驳回必须填写意见，原因和审核意见上限均为 2000 字符。数据库唯一约束和事务行锁阻止同一词条重复待审，事务内检查数据域与审核人身份。列表只显示原因摘要，点击“查看原因”阅读全文。

| 接口                                                 | 权限                                                   |
| ---------------------------------------------------- | ------------------------------------------------------ |
| `DELETE /api/v1/history/entries/:id`                 | 仅超级管理员                                           |
| `POST /api/v1/history/entries/:id/deletion-requests` | 对应数据域管理员、超级管理员                           |
| `GET /api/v1/history/deletion-requests/me`           | 管理员查看本人申请                                     |
| `GET /api/v1/history/deletion-requests`              | 普通管理员查看同域其他人的待审申请；超级管理员查看全部 |
| `POST /api/v1/history/deletion-requests/:id/review`  | 同域其他管理员；超级管理员允许自审                     |

所有删除采用软删除，保留词条、版本、历史投稿和附件，记录申请人、审核人及时间。删除与申请状态更新在同一事务完成。已删词条不会被后续投稿审核复活；原投稿人仍可查看自己的历史正文及附件。

部署先应用 `010_add_history_deletion_requests.sql` 再更新 API 和前端，Compose migrate 服务会自动执行。新表已纳入 `server/gen.yml`；重新生成模型可在 `server` 目录设置 `HISTORY_MODELGEN_DSN` 后执行 `go run ./cmd/history-modelgen`，不要手工修改生成代码。
