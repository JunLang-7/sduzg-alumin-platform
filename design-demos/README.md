# 校友详情与多段学籍编辑表单

**已确认的设计参考，保持 Draft PR，不合并到 `main`。正式开发从 `main` 另建分支，引用本 PR 和本文档；不把原型脚本当作业务实现。**

关联需求：[Issue #236](https://github.com/JunLang-7/sduzg-alumin-platform/issues/236)。当前原型为 `alumni-education.html`，可双击离线打开。全部人物、联系方式、任职与学籍为虚构示例，刷新后恢复。

## 查看页

沿用原有详情页标题、卡片、带边框信息表和档案区样式。

- 校友档案只放姓名、性别、手机号、邮箱、行业、工作单位、职务、通讯地址。
- 本科、硕士、博士学籍全部完整展开，每段都有独立的信息表、学位档案和学籍档案。
- 不提供添加、编辑、上传、移除等修改入口；有可下载文件时仍可下载。
- 管理员操作历史保留在底部，详情按个人信息或具体学籍显示修改前后值。

## 编辑表单

从校友管理列表的“编辑”打开，沿用原有820px弹窗与两列字段，不从查看页编辑。设置两个分区：

1. **个人信息**：姓名、性别、联系方式、行业、任职、通讯地址，只维护一份。
2. **学籍与档案**：各段学籍完整列出，分别维护培养类别、培养层次、年级、班级、届数、专业、培养方式、辅导员、导师、管理员备注及两类档案。新增学籍可有相同层次，已有学籍不能迁移培养类别；本次新增的学籍可从草稿移除。

所有字段和文件操作先保存在草稿中。“保存全部修改”统一提交到本地演示数据；取消、右上角关闭及Escape均丢弃草稿，不产生操作历史。姓名及各段年级必填，失败时切换到对应分区并定位字段。保存成功后，可从列表“查看”核对结果与操作历史。

本地预览链接支持 `?screen=list&edit=1` 直接打开第一位校友的编辑弹窗。离线文件也可以通过页面的“返回”进入列表再点击“编辑”。

## 权限与文件边界

顶部角色选择器为设计预览工具。本科管理员仅展示和维护本科段及相应学籍历史；共享个人信息历史仍可见。校友本人只查看本人信息和学籍，不提供管理员编辑及审计入口。管理员备注放在对应学籍下，避免跨数据域共享内部备注。

编辑中的文件仅加入当前页内存，选择后暂存草稿，不上传服务器。取消会丢弃；保存后关联具体学籍。文件控件沿用PDF、Word、JPG、PNG和单文件50MB限制。正式业务的身份绑定、个人信息写入、文件、数据域及审计授权仍须服务端实现与测试。
